## WHAT THIS APP IS

Ascendly is a premium self-improvement and study tracking web app for personal daily use. It tracks study sessions, daily habits and missions, tasks, and journal entries — with gamification woven in subtly. The goal is a product that feels like Linear or Raycast: fast, opinionated, beautiful, and genuinely useful.

## DESIGN DIRECTION

### Visual Identity

- Dark theme is the default. Warm undertones — backgrounds feel like dark paper, not cold black.
- Cream off-white text (#F0EAE0), never pure white.
- Primary color is warm orange. Accent is amber/gold.
- Glassmorphism on cards and modals — subtle, not overdone.
- Gradient text on key headings.
- Micro-interactions on every interactive element (hover transforms, opacity shifts, border transitions).
- Buttons: no box-shadow in default state. `1px solid var(--primary)` at 40% opacity by default. Full opacity + glow on hover only.
- Fully responsive: mobile, tablet, desktop. No horizontal overflow anywhere.

### Light / Dark Mode

- Dark is the default. App always opens in dark mode.
- Light mode toggled via sun/moon icon button in the topbar.
- Smooth CSS transition (~300ms) on all color properties when switching.
- Implemented via `data-theme="light"` on `<html>` element.
- Light mode palette — warm cream/paper, not cold white:

```css
[data-theme="light"] {
  --bg:          #F5F0E8;
  --bg-elevated: #EDE8DF;
  --bg-card:     #E8E2D8;
  --bg-hover:    #DDD8CE;
  --border:      #C8C0B0;
  --text:        #1A1410;
  --text-muted:  #6A5E50;
  --text-dim:    #9A8E80;
}
```

Brand colors stay the same in both modes.

## MODULE 1 — STUDY TRACKER

- Log study sessions: topic, hours, difficulty (1–5), session note
- GitHub-style heatmap — empty cells invisible by default, visible on hover; filled always visible; grid via gap
- Monthly goal: target hours + progress
- Rhythm metrics: weekly average, progress vs. goal
- **Monthly reset:** auto-snapshot on 1st (total hours, avg difficulty, top topics) + month-over-month bar chart

---

## MODULE 2 — PERSONAL GROWTH / DAILY

Most-used screen. Structured as follows:

### Mission sections
Three columns: **Morning / Afternoon / Evening**
- Fixed pillars (3 defaults, editable in Settings) + extras addable per day
- Items draggable between columns via dnd-kit
- Checkbox to complete each mission

### Habit Tracker
Displayed below missions. Two groups: **Positive Habits** and **Negative Habits**.

Each habit:
- Name + category (predefined or custom)
- Toggle to log for today
- Optional time duration field (e.g. "45 min")
- Managed in Settings — add, remove, edit, toggle positive/negative

Predefined positive habits (examples): Study, Reading, Exercise, Meditation, Cold shower
Predefined negative habits (examples): Social media > 1h, Sugar, Skipping workout

### Daily Close
Fixed section at the bottom of the page. Filled once per day:
- **Day note:** 1–10 slider with visual feedback
- **Day type:** Work Day / Day Off 1 / Day Off 2 / Day Off 3
- **Comment:** optional textarea
- **Day summary chart:** horizontal bar or donut showing positive vs negative habits (count + time)
- **"Close Day" button** — saves everything to DB

### Analytics tab (within Growth page)
Separate tab/view inside the Growth page:
- Period selector: Today / This Week / This Month / All Time
- Heatmap per habit (consistency over last 3 months)
- Monthly chart: positive vs negative habits (time + count)
- Trend lines per habit over time
- Average day note over time
- Work days vs day off breakdown

### Persistence
- Each day's data saved individually in DB
- Monthly snapshot auto-saved on 1st of month (avg note, habit totals, top habits, work/off count)
- All-time view aggregates all monthly snapshots

## MODULE 4 — JOURNALING

Fully implemented:

- Text editor for entries (multiple per day, timestamped)
- Day rating/score per entry
- GitHub-style heatmap of past entries (color = score)
- Past entries list: date, preview, score badge, expandable

**AI analysis via Groq (free):**
- Model: `llama3-8b-8192`
- User clicks "Analyse" → entry sent to Groq
- Response displayed inline in 3 sections: Reflection / Patterns / Suggestions
- Primary color left border on response panel
- "Powered by Groq" in dim text
- Backend route: `POST /api/journal/:id/analyse` — calls Groq, saves response to DB
- Loading state while waiting, error state if Groq fails
- All entries and AI responses stored in DB

Compact widget in Dashboard. Subtle indicator in sidebar.
